How Image Quality Affects OCR: A Small Reproducible Test

The same text can produce different recognition errors after a change in image quality. Here are all nine results from three original English passages, one font, and one fixed Tesseract configuration.

Published by Nedal / Idraaak · Experiment design: 17 October 2026 · Synthetic samples · AI-assisted code, analysis and writing

Measured pooled character error rates: clear original: 0.00%; reduced resolution: 10.42%; skewed +3°: 0.00%.

These are edit-distance measurements against known source text, not the engine’s confidence scores. Each condition contains the same three passages and 1,737 reference characters in total. Lower CER means fewer edits were needed.

What can a smaller or tilted image change?

OCR turns pixels into characters, so a readable-looking preview is not enough to establish that the extracted words are correct. This test asks how the character edit count changes when resolution is reduced or the page is tilted, while the text, font, contrast, recognition engine and command settings stay fixed.

The experiment is deliberately small. It measures these nine inputs rather than estimating the accuracy of OCR in general.

A fixed design, chosen before the main runs

Samples A, B and C contain 93, 95 and 94 words respectively. They are original fictional passages about a workshop, a garden notebook and an archive. Their original texts are the ground truth; none contains personal records.

  • Clear originals: 1600 × 1000 grayscale pixels, black text on white, DejaVu Sans 2.37 regular at 32 pixels, 80-pixel margins and 48-pixel line spacing. Wrapping is based on the same font’s measured pixel width. No text comes from an image generator.
  • Reduced resolution: resize each complete original to 400 × 250 with Pillow LANCZOS: one quarter of each dimension and one sixteenth of the pixels. No extra sharpening or thresholding.
  • Skewed: rotate each original counterclockwise by 3° with BICUBIC interpolation and an expanded white canvas. Expansion keeps the whole source image, including every line, within the frame. Rotation necessarily adds border space and resamples edges; it is not a pure change to angle at the pixel level.

All nine files are lossless PNGs. Nominal DPI metadata and the OCR --dpi 300 argument are identical for all conditions, so the reduced image genuinely has fewer pixels per character rather than a different OCR DPI setting. The design file was committed before the first main OCR run. There was no search across settings after inspecting the errors.

Engine: tesseract 5.3.4, English only, LSTM engine mode 1, page segmentation mode 6 (one uniform block of text), one CPU thread. It runs as a local command-line program on a GitHub Actions Ubuntu 24.04 runner; no external OCR API is called. The same bundled English model and command options are used for every image. The operating system, package versions, font hash, model hash and full engine version are in the environment record.

tesseract images/A-original.png raw/A-original \
  --tessdata-dir models -l eng --oem 1 --psm 6 --dpi 300

Only the input and output file names change between runs. Tesseract still performs its own internal processing; this test does not claim to disable internal skew handling or binarization.

How the character error rate was calculated

For scoring, every run of whitespace is replaced by one ASCII space and leading/trailing whitespace is removed. That treats OCR line wrapping as layout, not a character error. Case, punctuation, digits and every other non-whitespace code point are preserved. Nothing is corrected by hand, and no punctuation is removed to improve a score.

CER = (substitutions + deletions + insertions) ÷ characters in the normalized reference. Spaces remaining after normalization count in that denominator. The numerator is the minimum unit-cost Levenshtein edit distance. The stored alignment uses substitution, deletion, then insertion as its deterministic tie preference; another minimum alignment can assign edits differently without changing the total.

The pooled rates sum edit counts across A, B and C, then divide by the summed reference length. They are not an unweighted average of the three percentages. CER is an error rate and can exceed 100% when insertions are numerous; it is not a confidence score.

What these inputs show—and what they cannot

Reduced resolution produced more character errors than the clear original across the three paired samples. The pooled CER was 10.42%, compared with 0.00% for the originals.

Skewed +3° produced no more character errors than the clear original across the three paired samples. The pooled CER was 0.00%, compared with 0.00% for the originals.

Resolution reduction removes pixel information; rotating an image changes the alignment of its text lines and resamples letter edges. Those mechanisms are consistent with Tesseract’s official quality guidance, but the size and even direction of the measured effects here belong to these particular passages and settings.

There are only three artificial English texts, one regular font, one layout and one engine/model combination. The experiment does not test Arabic, handwriting, photographs, shadows, compression artifacts, complex columns or tables. It does not isolate every internal OCR processing step, compare OCR products, establish statistical reliability across documents, or identify a universally safe size or skew threshold.

A practical extraction workflow

  1. Keep a detailed source image. Tesseract’s documentation recommends adequate resolution and discusses the importance of character size. Merely changing a DPI label cannot restore pixels already discarded.
  2. Keep text lines level when possible. Its official guide recommends deskewing when tilt interferes with line segmentation. This experiment uses one 3° angle, not a universal cutoff.
  3. Match the layout setting to the input. Mode 6 was chosen because these samples are a single text block. It should not be treated as the best mode for an arbitrary full page.
  4. Check the extracted characters. Compare a few lines against the source, especially numbers, punctuation and names. A low average error rate can still conceal a wrong value in an important field.

When choosing a desktop workflow, look for controls that let you retain the source image, select the correct language and inspect the extracted text. Reproduce the experiment

The public repository contains the frozen design, original texts, image generator, OCR commands, raw outputs, normalized scoring texts, CSV, edit alignments and the report builder. It also includes the font and language model with their respective license notices. Input and output file hashes are recorded in the evidence manifest.

python -m pip install -r requirements.txt
python experiment.py
python build_report.py

Install the exact free Ubuntu packages listed in README first. The command-line engine stays fixed at 5.3.4. Rerunning with a different renderer, font, model or engine can change pixels or outputs, so compare their recorded hashes before attributing a change solely to image quality.
